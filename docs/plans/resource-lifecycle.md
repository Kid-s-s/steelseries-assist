# 常驻资源生命周期

按资源归属统一管理后台任务、会话与退出清理。

## 1. WebSocket 会话

`SonarEventClient.StartAsync` 和 `DisposeAsync` 共用串行生命周期入口。启动新会话前，取消并等待旧接收任务退出，然后释放旧取消源。令牌在启动任务前取得；最终释放会等待当前会话结束，之后拒绝再次启动。

连接、接收和退避均可取消。旧任务结束前不会启动新接收循环，因此旧会话的断开通知不会落到新会话之后。正常远端关闭也进入退避，避免空转重连。

## 4. 退出与端点切换

`AsyncOperationScope` 管理在途任务：停止接收新工作，取消令牌，等待包括异步收尾在内的任务完成，最后释放取消源。主窗口的状态读取、降级轮询、EQ 加载和命令使用同一窗口级作用域；音量写入器也使用相同规则管理工作任务。

ChatMix 每个端点会话拥有独立的 HTTP 客户端和操作作用域。换端点时先停止并等待旧会话，再释放其客户端、创建新会话；不会直接释放仍被请求使用的客户端。

主窗口退出先停定时器并解除后台事件订阅，再异步等待后台接收、音量写入、ChatMix 和窗口在途操作结束，最终释放 HTTP 客户端。UI 线程不再同步阻塞等待这些任务。程序关闭窗口和最终退出均走该流程；普通右上角关闭仍只收起到托盘。托盘菜单也明确释放。

## 验证

20 项自动测试，包括 300 次并发重启、在途任务与异步收尾等待、音量写入取消和重复释放。另有本地延迟 HTTP 服务器下的真实 WPF 会话切换及退出检查。长期运行与休眠唤醒仍需实测。
